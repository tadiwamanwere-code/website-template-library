A real run, replayed byte for byte.

// what you are watching.
A rAF-driven state machine types each character with per-token latency jitter, then prints output with the real command's measured pauses. It pauses off-screen and shows the final transcript instantly under prefers-reduced-motion.

// orbit why
Every rebuild is explainable. orbit why <target> prints the exact input whose hash moved and the downstream set it invalidated. No "cache miss, good luck".

// regions.
Blobs replicate to fra1, iad1 and sin1 within 400ms of a push. A runner always reads from its nearest region and falls back to origin on a miss.

§ 02how a target resolves

Four steps, no magic.

01
Declare
A task is inputs, a command, and outputs. Globs are resolved against the git index, not the filesystem.
02
Fingerprint
BLAKE3 over file contents, the command string, the resolved toolchain, and the declared env allowlist.
03
Resolve
Local CAS first, then the nearest edge region. A hit is a range request; nothing is decompressed twice.
04
Restore
Outputs are written with verify-on-write. Stdout and stderr of the original run are replayed too.

§ 03benchmarks

The numbers, including the one we lose.

Measured on helios-kernel @ e41c8b2 — 14,208 targets across TypeScript, Rust and Go — on a 32-core c7a.8xlarge runner, 10 consecutive runs, median reported. Scripts to reproduce are in bench/.

// why we publish the loss.
Fingerprinting 41,902 files costs roughly 36s of wall time. On a genuinely cold cache orbit is 5.9% slower than plain make. You will hit that on the first CI run after a dependency bump — it is the price of determinism, and hiding it would be dishonest.

§ 04design notes
4.1

Determinism is a property of the inputs, not the tool.

Most caches key on a lockfile hash and a directory mtime. That is why they silently miss after a rebase, and why they silently hit after a toolchain upgrade. orbit refuses to guess: a task declares its inputs explicitly, and an undeclared file that the command reads is a HERMETICITY_VIOLATION under --strict, detected via a syscall filter on Linux and a VFS shim on macOS.

strict modedetected drift
$ orbit build api:compile --strict

  ✗ HERMETICITY_VIOLATION  api:compile
    read  /etc/ssl/openssl.cnf        (undeclared)
    read  ../../.env.local             (outside workspace)

  # fix: declare it, or drop it. orbit will not cache a lie.

// mtime is not identity.
orbit never reads mtime. Content only. A touch * across the repo changes nothing and restores everything.

// eviction.
Edge regions keep a 30-day LRU with a 2 TB per-org ceiling. Blobs referenced by a protected branch tag are pinned and never evicted.

The cache is content-addressed, so it is also a supply chain record.

Because every artifact is stored under the BLAKE3 of its bytes and every key is derived from a declared input set, the cache doubles as a provenance log. orbit attest emits an in-toto v1 statement for any restored target: which key, which inputs, which toolchain, which runner identity signed the push.

4.3

Adoption is incremental or it does not happen.

orbit init reads your existing package manifests and emits a draft orbit.toml covering the tasks it can prove are safe. Everything else stays uncached until you opt it in. Teams typically land the first PR in an afternoon and reach 90% coverage over a few weeks.

There is no server to run. The open-source CLI works fully offline against ~/.orbit; the hosted edge CAS is the only paid part, and it speaks a documented, implementable protocol. Self-host it with orbit-cas — same binary, --serve.

// exit cost.
If you delete orbit tomorrow, your build commands still run. The config is a description of what you already had.

§ 05architecture

Five hops from source to restored artifact.

No coordinator, no scheduler, no lease negotiation. Each runner resolves independently and pushes what it built. The only shared state is immutable, content-addressed bytes.

Internals, answered properly

It is not enforced — it is measured. orbit hashes the resolved toolchain (compiler version, ABI, target triple), the declared env allowlist, and the byte content of every declared input. If two machines produce the same key they had the same inputs, by construction.

Where builds are genuinely non-deterministic — embedded timestamps, non-sorted map iteration — orbit doctor --nondeterminism builds the same target twice on the same machine and diffs the output trees. It reports the offending files rather than pretending the problem does not exist.

Two things: 32-byte content keys, and the compressed output trees you explicitly declared under outputs. Source files are never uploaded. Keys are opaque hashes — the CAS cannot enumerate your file names from them.

Blobs are encrypted at rest with a per-org key, and you can supply your own via ORBIT_CAS_KEY, in which case the edge stores ciphertext it cannot read. Push is opt-in per task with push = false.

A restore is verified against the key before anything is written to the working tree; a mismatch evicts the blob and falls through to a local rebuild. Because the key is the hash of the content, forging an entry requires a BLAKE3 preimage.

Writes are additionally gated: only runners with a valid OIDC identity for your org can push, and --require-attestation makes restores refuse any blob not signed by an allowed builder identity.

No. orbit shells out to the command you give it. There is no DSL for describing compilation, no Starlark, no ruleset to port. The orbit.toml for a 14,000-target monorepo is typically under 400 lines because tasks inherit from workspace-level defaults.

Every remote call has a 250ms connect budget and a hard fail-open policy: on timeout, orbit logs a warning, falls back to the local store, and builds. A network outage makes your build slower, never broken. --offline makes that the default.
